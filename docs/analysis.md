# Analysis

## 1. Current autonomous analyzer

The repository currently includes:

```text
tools/analysis/analyze_autonomous_results.py
```

Run it through:

```bash
make analyze \
  SUMMARY=outputs/autonomous_n20_state0/sweep_summary.json \
  ANALYSIS_OUTPUT=results/autonomous_n20_state0
```

This tool summarizes the Phase 1 autonomous condition sweep. It should not be
used as the final cross-mode analyzer because shared-autonomy experiments add
operator activity, dynamic arbitration weights, scheduler waits, and mode
pairing requirements.

## 2. Unified comparison analyzer

Generate the general autonomous/operator comparison with:

```bash
make analyze-comparison
```

The default operator roots are the versioned `saps_libero_teleoperation_v2` and
`saps_libero_shared_autonomy_v2` session outputs. The autonomous default remains
the completed Phase 1 `autonomous_deterministic_n20_state0_v1` collection.

Override `AUTONOMOUS_RESULTS`, `TELEOP_RESULTS`, `SHARED_RESULTS`, or
`COMPARISON_OUTPUT` when analyzing another collection. Outputs include:

```text
episode_metrics.csv
mode_summary.csv
condition_mode_summary.csv
paired_autonomous_comparisons.csv
paired_mode_summary.csv
validation_report.json
REPORT.md
plots/
```

The analyzer uses simulated control time, end-effector arc length, official task
success, and the paper's intervention convention: 0% for autonomy, 100% for
teleoperation, and motion-active step fraction for shared autonomy. It validates
policy-seed pairing and reports incomplete scheduled coverage rather than
silently treating collected subsets as complete experiments.

## 3. Pairing key

Matched comparisons must use:

```text
condition_id
trial_index
initial_state_index
policy_episode_seed
```

The analyzer must report missing or duplicated members of a matched set rather
than silently dropping them.

## 4. Episode metrics

At minimum:

- official task success;
- control steps and simulated control seconds;
- wall-clock elapsed time;
- termination reason;
- policy replan count;
- policy inference latency;
- scheduler wait ticks and duration;
- human-active steps and fraction;
- intervention segment count and duration;
- configured and effective autonomy weights;
- cosine-similarity statistics;
- action validity and arbitration-equation checks.

## 5. Aggregation

Summaries should be generated by:

- arbitration mode;
- perturbation condition;
- radial perturbation distance;
- mode × condition;
- matched trial set.

Report denominators explicitly. Success rates must distinguish all scheduled
episodes, valid completed episodes, and any predefined exclusion set.

## 6. Inferential methods are outside the completed pilot

The completed matched LIBERO pilot is descriptive infrastructure evidence. No
significance test, post-hoc arbitration tuning, or causal recovery analysis is
part of its accepted interpretation. Any later powered comparison would require
a separately frozen design and inferential plan; it must not relabel or extend
the completed pilot post hoc.

The analysis code must preserve raw episode-level tables so alternative models
can be evaluated without rerunning experiments.

## 7. Validation before analysis

The analyzer should fail loudly or produce a blocking validation report for:

- missing manifest entries;
- duplicate completed outputs;
- mismatched seeds or condition IDs;
- unreadable JSON;
- non-finite actions;
- incorrect action dimensions;
- invalid arbitration parameters;
- non-monotonic replan indices;
- incomplete operator metadata;
- output directories inconsistent with summaries.

## 8. Archived matched-pilot analyzer

Gate 2 v2 uses a dedicated read-only analyzer because it requires frozen
60-outcome denominators, selected-redo semantics, fixed/cosine arbitration
diagnostics, separate simulated and wall timing, policy-wait reconstruction,
SpaceMouse-profile validation, and exact three-mode triplets:

```bash
make gate2-analysis
```

The completed archive reports 60/60 analyzable outcomes, 20/20 exact triplets,
valid analysis, and no blocking errors. See
[`simulation_saps_baseline.md`](simulation_saps_baseline.md) for the canonical
interpretation and [`gate2_operator_pilot.md`](gate2_operator_pilot.md) for the
frozen artifact list and numerical thresholds. The general comparison analyzer
is not a substitute for this archival command.
