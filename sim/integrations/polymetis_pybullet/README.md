# Pinned Polymetis/PyBullet Panda probe

This integration builds the DROID-pinned Fairo revision `0a01a7fa7a7c65b2f9a3aebf5e79040940daf9d2` (DROID revision `33ae6a67274f36d2e29525b86f23a56616ef43a7`) in a CPU-only Docker image. It uses Fairo's bundled **Panda**, not FR3. It does not run OpenPI, Isaac Sim, or a physical robot.

## Build and run

From the repository root:

```bash
docker build -t saps-polymetis-pybullet:0a01a7f sim/integrations/polymetis_pybullet
mkdir -p outputs/polymetis_pybullet
docker run --rm --init \
  --user "$(id -u):$(id -g)" \
  -e HOME=/tmp \
  -e GIT_CONFIG_COUNT=1 \
  -e GIT_CONFIG_KEY_0=safe.directory \
  -e GIT_CONFIG_VALUE_0=/opt/fairo \
  -v "$PWD/sim/integrations/polymetis_pybullet:/integration:ro" \
  -v "$PWD/outputs/polymetis_pybullet:/output" \
  saps-polymetis-pybullet:0a01a7f \
  python /integration/direct_step_hold.py \
    --port 51073 --output /output/my_unique_trial
```

Use a new output directory for each run; the script refuses to overwrite one. Port `51073` is checked before launch, bound only to container loopback, and never published to the host. The script starts the pinned native `run_server`, composes `robot_client=franka_sim`, `robot_model=franka_panda`, `gui=false`, and `use_real_time=false`, then runs the PyBullet client in a stoppable thread. It terminates the policy, joins the client thread, stops the server, and checks that the port closed. A zero exit status means those checks and fault checks passed.

The [pinned installation instructions](https://github.com/facebookresearch/fairo/blob/0a01a7fa7a7c65b2f9a3aebf5e79040940daf9d2/polymetis/docs/source/installation.md) specify Python 3.8 and a native build. This image pins the micromamba base by digest, uses [exact resolved Linux-64 package URLs and hashes](conda-lock-linux-64.txt), and verifies Fairo's Git SHA before building the server with hardware support disabled. [environment.yml](environment.yml) records the human-readable dependency constraints. Key resolved versions are Python 3.8.19, PyTorch 1.13.1 CPU, MKL 2022.0.1, Pinocchio 2.5.2, gRPC C++ 1.41.1, Python gRPC 1.46.0, protobuf 3.18.1, Hydra 1.0.6, and PyBullet 3.17. The exact image ID and file SHA-256 values for the successful trial are in `outputs/polymetis_pybullet/trial_09/provenance.json`.

Two isolated compatibility patches are applied after checking out the pin: [one adds the missing C++ `cstddef` include](patches/0001-include-cstddef.patch), and [one avoids importing unused Habitat/MuJoCo clients](patches/0002-pybullet-only-imports.patch). Neither changes controller equations or targets. The first build failed on the missing include; a subsequent link failed with solver-selected MKL 2024, so the environment follows Fairo's MKL 2022 pin. The upstream `bullet_sim` YAML has unresolved gain references in the plain launch config. `franka_sim` supplies all gain values and launched successfully here. The upstream all-in-one launcher reached the test but did not shut its blocking client loop down cleanly via SIGTERM; the separate lifecycle in this script did.

## Verified trial

`outputs/polymetis_pybullet/trial_09/` contains the raw [sampled step/hold response](../../../outputs/polymetis_pybullet/trial_09/step_hold.json), [504 per-tick state records](../../../outputs/polymetis_pybullet/trial_09/server_policy_log.json), [derived metrics](../../../outputs/polymetis_pybullet/trial_09/summary.json), [server log](../../../outputs/polymetis_pybullet/trial_09/server.log), and [provenance](../../../outputs/polymetis_pybullet/trial_09/provenance.json).

`outputs/` is ignored generated data; retain the trial files separately if the evidence must outlive this workspace.

The loaded model was `franka_panda/panda_arm.urdf`, 7 DOF, `panda_link8`. `start_cartesian_impedance()` created the pinned `HybridJointImpedanceControl` with simulator defaults `Kq=[20,30,25,25,15,10,10]`, `Kqd=[1,1.5,1,1,0.5,0.5,0.5]`, `Kx=[100,100,100,40,40,40]`, and `Kxd=[1,1,1,0.2,0.2,0.2]`. These are **simulation gains**, not DROID's physical hardware gains. The client metadata reported 240 Hz; PyBullet's fixed step was 1/240 s, and the median timestamp spacing in the server policy log was 4.167 ms (239.98 Hz).

From stationary q (`|dq|` near machine zero), joint 1 was commanded +0.030 rad and held for about 2.07 s of logged controller time. The server accepted the update at log index 6. Its first 66.7 ms displacement was 11.3% of command; it reached 50%, 90%, and 95% at 0.233, 0.518, and 1.179 s. The final measured displacement was 99.4% of command, with 0.000178 rad target error. Peak absolute reported joint-1 computed torque was 2.67 Nm. All logged fault codes were zero; reported commands succeeded; the policy was terminated, client thread stopped, server exited on SIGTERM, and the port closed. Reported simulated motor torque is generated by the PyBullet client, not an independent physical torque sensor.

The Panda URDF emits a warning for missing inertial data on its base link. Pinned torchcontrol loads two built libraries from the local build directory after not finding them under the Conda prefix. These warnings did not prevent the verified run. No FR3 model, physical DROID gain file, physical response, gripper dynamics, or contact equivalence is established here.
